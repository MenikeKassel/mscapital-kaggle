## 二、提案: 工程化目标语法

```
^(P[0-9]R?|C|E|M|S)-[0-9]{2}[a-z]?$
```

- 系列前缀 = 阶段目录 (P0~P7, C, E, M, S)
- 两位序号 = 阶段内时间序
- 小写变体 = 仅用于"同一实验的臂" (消融 arm), **独立实验必须独立序号**

### 配套机制 (工程化落点)

1. **自动分配器**: `new_experiment.py <phase> <name>` → 读 registry 自动取下一序号 + 建目录 + README 骨架 (杜绝拍脑袋编号)
2. **一致性测试**: `tests/test_registry_consistency.py` — pytest 校验: ID 语法正则 / 唯一性 / 目录存在 / script_path·report_path 真实存在 / Alias 无重复。改坏编号 = 测试红
3. **新文件命名纪律**: 新脚本/报告按 `p{n}_{nn}_{name}.py` 命名 (与 ID 对齐); 旧文件不重命名 (保持可运行性 + git 历史), 靠 registry 映射

## 三、红线 (评审时不要建议打破)

1. 历史编号可追溯性零损失 (Alias 列兜底, 已实现)
2. 旧脚本/报告**文件名不重命名** (147 个脚本硬编码路径依赖, 重命名破坏可运行性)
3. pytest 112 全过不得回归
4. 不做"全量重写 registry/目录"式重构 (成本已付, 只需增量收敛)
5. 提交事件命名空间 (v1~v8b 提交链) 与实验 ID 必须可区分

## 四、开放决策点 (请逐条给出明确意见 + 理由)

1. **baseline 历史区豁免 vs 全量收敛**: A1~H1 (14 个早期表格实验) 保留原字母编号 (显式 LEGACY 豁免区), 还是也收敛为 P0-NN? 权衡: 豁免=改动小但语法有例外; 收敛=语法纯净但早期文档 (RESULTS.md 首段) 全部对不上
2. **变体后缀滥用回溯**: P4-10~E / P1-01~e 历史上把独立实验编成变体后缀 (A/C/D/E 是 4 个不同实验)。是否值得回溯拆成独立序号 (P4-08a~e → P4-08/P4-09/P4-10/P4-11)? 报告文件名 (p4_08a_loss_ablation.py) 已按变体命名
3. **第 3 轮重编号的价值判断**: 编号已改过 2 轮 (唯一性轮 + 消歧轮)。第 3 轮语法收敛是否值得? 还是应该"语法只约束新实验, 旧 ID 冻结" (工程上 ID 稳定 > 语法纯净)?
4. **S-04 vs S-04**: 提交事件命名空间哪个更好? (S-04: 语法纯净可正则; S-04: 语义直白与 v 系列提交名对应)
5. **大小写统一 (P5-02→P5-02i) 收益**: 值得为此改 registry + 目录 + docs 引用吗? 还是保留大写 (历史报告大写多)
6. **一致性测试的位置**: pytest 里加 test_registry_consistency.py 是否合适? 还是独立校验脚本 (registry 改动不频繁, 每次 pytest 都跑是否有噪音)?
7. **目录名 vs ID 的对应**: 当前目录 `experiments/<phase>/<ID>_<name>/` (name 是中文截断) — 中文截断名在跨平台/脚本处理是否有隐患? 建议纯 ASCII slug 吗?
